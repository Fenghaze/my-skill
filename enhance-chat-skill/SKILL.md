# 增强对话规划技能

## 概述

本技能通过严谨的设计树方法论增强规划模式下的规划过程。它系统性地探索需求、提出详细问题、并确保完整的功能规范，从而最小化从设计到实现过程中的 bug。

## 使用时机

**强制触发规则：凡涉及功能相关的请求，一律先调用此技能。**

包括但不限于：
1. 用户请求新增功能（如"添加XX功能"、"实现XX"）
2. 用户请求修改或优化现有功能（如"改进XX"、"重构XX"）
3. 用户请求删除功能（如"移除XX功能"）
4. 用户请求修复功能bug（如"XX功能有问题"、"修复XX"）
5. 用户进入规划模式进行软件设计任务
6. 用户使用 /plan 命令或类似规划命令
7. 用户询问架构设计或系统规划
8. **任何需要写代码才能完成的任务请求**（除非是简单的读文件、看代码、查文档）

**禁止行为：**
- 禁止在未经此技能进行需求分析和颗粒度对齐的情况下直接开始写代码
- 禁止对模糊需求直接实现，必须先通过此技能澄清

## 设计树方法论

设计树将需求从高层目标分解为具体的、可测试的规范：

```
目标（用户目标）
  └─ 领域分析
       └─ 用例场景
            └─ 功能点
                 └─ 需求细节
                      └─ 边界情况
                           └─ 异常处理
```

## 规划工作流程

### 阶段0：颗粒度对齐

**目的：** 明确项目类型，确定后续规划的广度和深度

**必须询问用户：**

> "请确认本次开发的颗粒度：
> 1. **0-1项目搭建** - 从零开始的新项目，需要完整技术选型、架构设计
> 2. **已存在项目的业务功能实现** - 在现有项目上添加功能，最小化改动
> 3. **功能bug修复** - 修复现有功能的错误，快速定位"

**不同颗粒度的规划策略：**

| 颗粒度 | 规划深度 | 设计树展开 | token消耗 | 目标 |
|-------|---------|-----------|----------|------|
| 0-1项目搭建 | 完整展开 | 全链路 | 高 | 技术选型+架构设计 |
| 业务功能实现 | 中等 | 聚焦新增部分 | 中 | 最小化改动 |
| Bug修复 | 轻量 | 问题定位 | 低 | 快速修复 |

**0-1项目搭建：** 完整使用设计树方法论，从技术选型→架构设计→详细设计

**业务功能实现：**
- 聚焦于「新增/修改」部分
- 优先复用现有架构和模式
- 直接读取现有代码推断技术栈和架构（减少交互）
- 设计树只展开新增功能的路径

**Bug修复：**
- 不使用完整设计树
- 直接定位问题根因
- 问：「出错的输入是什么？预期行为是什么？」
- 给出最小改动修复方案

### 阶段1：深度需求收集

**根据颗粒度调整问题深度：**

**0-1项目搭建 - 完整提问：**
1. **业务背景**
   - 我们要解决什么问题？
   - 用户是谁？
   - 成功指标是什么？

2. **功能需求**
   - 核心功能有哪些？
   - 有哪些边界情况？
   - 错误时应该如何处理？

3. **非功能需求**
   - 性能要求（延迟、吞吐量）
   - 可扩展性考虑
   - 安全要求
   - 可用性要求

4. **集成点**
   - 外部 API/依赖
   - 数据源
   - 需要集成的现有系统

5. **约束条件**
   - 技术约束（语言、框架）
   - 时间/预算约束
   - 团队专业能力

**业务功能实现 - 轻量提问：**
- 新增功能的核心需求是什么？
- 对现有架构的影响范围？
- 需要复用哪些现有组件/模式？

**Bug修复 - 快速提问：**
- 出错的输入是什么？
- 预期行为是什么？
- 实际行为是什么？
- 最近一次正常是什么时候？

### 阶段2：设计树展开

**根据颗粒度调整展开深度：**

**0-1项目搭建 - 完整展开：**

对每个功能进行系统性展开：

```
功能：[功能名称]
├─ 主路径：[正常流程描述]
├─ 替代路径：[替代流程]
├─ 错误场景：
│   ├─ [错误类型1] → [恢复操作]
│   ├─ [错误类型2] → [恢复操作]
│   └─ ...
├─ 边界情况：
│   ├─ [边界情况1] → [预期行为]
│   ├─ [边界情况2] → [预期行为]
│   └─ ...
├─ 输入验证：
│   ├─ [字段1]：[约束、有效范围]
│   ├─ [字段2]：[约束、有效范围]
│   └─ ...
└─ 输出规范：
    ├─ [成功输出格式]
    ├─ [错误输出格式]
    └─ ...
```

**业务功能实现 - 聚焦新增：**
- 只展开新增/修改的功能路径
- 复用部分用「沿用现有架构」标注

**Bug修复 - 跳过设计树：**
直接进入问题定位

### 阶段3：风险评估

**根据颗粒度调整：**

| 颗粒度 | 风险评估深度 |
|-------|------------|
| 0-1项目搭建 | 完整风险矩阵 |
| 业务功能实现 | 聚焦改动带来的风险 |
| Bug修复 | 最小化改动，避免引入新问题 |

### 阶段4：验证策略

**根据颗粒度调整：**

| 颗粒度 | 验证策略 |
|-------|---------|
| 0-1项目搭建 | 完整测试策略 + 验收标准 |
| 业务功能实现 | 聚焦新功能测试 |
| Bug修复 | 复现问题 → 修复 → 验证 |

## 必问问题类别

### 通用问题
- "此功能的精确用户旅程是什么？"
- "当 X 失败时会发生什么？"
- "系统应该如何处理 [边界情况]？"
- "性能期望是什么？"
- "谁需要批准此设计？"

### 数据问题
- "需要存储什么数据？"
- "如何处理数据验证？"
- "数据关系是什么？"
- "如何处理并发访问？"

### API/接口问题
- "精确的输入格式是什么？"
- "精确的输出格式是什么？"
- "错误代码及其含义是什么？"
- "需要什么认证/授权？"

### 用户体验问题
- "成功时用户应该看到什么？"
- "每种错误类型时用户应该看到什么？"
- "有什么加载状态需要处理？"
- "是否需要任何反馈或确认？"

### 部署问题
- "如何部署此功能？"
- "能否无停机部署？"
- "需要什么监控？"
- "回滚程序是什么？"

## 交付成果

使用此技能时，输出应包括：

1. **需求摘要**：完整理解需要构建什么
2. **设计树可视化**：系统的分层分解
3. **详细规格**：对每个功能包括：
   - 描述
   - 输入/输出规范
   - 错误处理
   - 边界情况
   - 测试场景
4. **风险矩阵**：已识别的风险及缓解策略
5. **实施计划**：带依赖关系的分步执行计划

**颗粒度对交付的影响：**
- 0-1项目搭建：完整交付以上5项
- 业务功能实现：聚焦1-3项，实施计划侧重新增部分
- Bug修复：问题描述 + 根因 + 修复方案 + 验证方法

## 应避免的反模式

- ❌ 未确认就做假设
- ❌ 因为"罕见"而跳过边界情况
- ❌ 延迟错误处理决策
- ❌ 编写模糊的规范
- ❌ 忽略性能影响
- ❌ 忘记安全影响
- ❌ 不考虑向后兼容性
- ❌ 规划时没有测试策略
- ❌ 对所有项目使用相同的规划深度（应按颗粒度调整）

## 应用示例

### 0-1项目搭建示例

当用户说"新建一个电商后台系统"时，技能应展开为完整设计树。

### 业务功能实现示例

当用户说"在现有电商系统中添加拼团功能"时：
- 先读取现有代码推断架构
- 设计树只展开拼团功能相关路径
- 复用现有用户/订单/支付模块

### Bug修复示例

当用户说"用户无法登录，报500错误"时：
- 不使用完整设计树
- 直接定位问题根因
- 给出最小改动修复方案

## 与 Claude Code 的集成

此技能通过以下方式与 Claude Code 的规划模式集成：
1. 拦截规划模式进入
2. 先进行颗粒度对齐
3. 根据颗粒度应用设计树方法论
4. 在继续之前提出针对性问题
5. 生成符合颗粒度的规划文档
